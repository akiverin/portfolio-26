# Hero «Ясный проход» — проверка

Дата: 24 октября 2026. **34 проверки прошли; необработанных ошибок JavaScript и ошибок console.error нет.** Подробные измерения: [report.json](report.json).

Проверки выполнены Playwright в Chromium с программным WebGL SwiftShader. Публичные проверки и оставшиеся проверки выполнялись последовательно; финальные изображения планшета и production-сборки сняты после исправления позиции персонажа. Промежуточные проблемы тестового стенда (идентичность модулей Vite, границы flex-контейнера, остановка compositor в headless) исправлены в тестовом сценарии.

## Что проверено

- Живые цифры: при неподвижном курсоре меняется 5.2171% немаскированных пикселей сцены за интервал 1.2 секунды; HTML-текст, персонаж и элементы управления исключены из сравнения.
- Параллакс зависит от прокрутки. При остановленной сцене перемещение мыши меняет 0% пикселей, в режиме анимации мышь не передаёт смещение в shader.
- Прокрутка окна и внутреннего контейнера аккаунта передаёт нормализованную глубину в shader (`u_scroll` около 0.30 после прокрутки на 300px).
- Выход Hero из viewport останавливает GPU-вызовы; возвращение возобновляет их.
- Первоначальный и изменённый во время работы `prefers-reduced-motion` останавливают цикл. Пользовательская кнопка паузы и повторный запуск работают.
- Кнопка паузы доступна при открытом уведомлении об обновлении сайта.
- Обработчик скрытия вкладки останавливает цикл. Для этой проверки уведомление `visibilitychange` и состояние `document.hidden` симулировались, чтобы сам процесс проверки продолжал работать.
- Разрешения 320×640, 390×844, 768×1024, 844×390, 1440×1000, 1920×1080, 3840×2160: один H1, заголовок не выходит по горизонтали, горизонтального переполнения страницы нет.
- На UHD Hero занимает все 3840px ширины. Backing canvas 2309×1299 (2 999 391 пиксель), в пределах бюджета 3 млн.
- Настоящий touch-контекст браузера 390×844 с DPR3 использует canvas 390×844, то есть DPR рендера ограничен 1.
- На планшете персонаж не пересекает фактические кнопки CTA (площадь пересечения 0px²).
- Ссылки Hero к проектам и контактам приводят целевые секции в область просмотра.
- Аккаунтная рамка проверена через симуляцию MobX-store в изолированном браузере. Реальный вход в Firebase и запись в аккаунт не выполнялись. Внутренняя прокрутка, геометрия рамки и остановка анимации работают.
- Отсутствие WebGL показывает статический фон без цикла анимации. Потеря WebGL-контекста переключает на фон, восстановление возвращает работающий renderer.
- Готовая production-сборка на `http://127.0.0.1:5174`: фон WebGL, заголовок и пауза/продолжение проверены отдельно от dev-сервера.

## Производительность и границы измерений

За стабильный замер 2.57 секунды **длительных задач основного потока (>50ms) не зарегистрировано**. P95 времени CPU на отправку draw-вызова — около 0.1ms. Это время отправки команды, а не время исполнения shader на GPU.

Headless SwiftShader показал медианный интервал compositor rAF около 83ms и P95 около 100ms. Этот программный compositor также иногда приостанавливал независимый rAF при отсутствии принудительной перерисовки; тесты обновляют его скриншотом после программной прокрутки. Эти цифры **не являются обещанием аппаратного FPS**. Аппаратная производительность конкретных устройств этим стендом не измерялась.

## Повторный запуск

Из корня проекта при запущенном dev-сервере:

```sh
rtk proxy node scripts/hero-smoke.mjs
```

С дополнительной проверкой запущенной production-сборки:

```sh
rtk proxy env HERO_PRODUCTION_URL=http://127.0.0.1:5174 node scripts/hero-smoke.mjs
```

Сценарий использует Playwright и pngjs из bundled Codex runtime. На другой машине можно задать `HERO_QA_MODULES` (папка node_modules), `HERO_CHROME` (бинарник Chromium), `HERO_URL` и `HERO_QA_OUTPUT`.
